Ferrite over Bluetooth link protocol on the BT513 (FFE0/FFE1), Chrome Web Bluetooth

Connection

Not connected

Radio: MENU 0 9 2 1 Bluetooth on. The module advertises as "walkie-talkie". About 0.8 KB/s each way (the module's UART runs at 9600), so a screen readback takes a second or so.

Opening this page on an Android phone
  1. Web Bluetooth needs Chrome and a secure context: https or http://localhost. A LAN address (http://192.168.x.y:8000) is not secure, so Chrome hides Bluetooth there.
  2. On the Mac: cd tools/webble && python3 -m http.server 8000.
  3. Phone on USB with debugging on: adb reverse tcp:8000 tcp:8000, then open http://localhost:8000/ in the phone's Chrome. Allow Nearby devices (and Location on older Android) for Chrome.
  4. Not from a claude.ai artifact: it runs in a cross-origin iframe, and Bluetooth in an iframe needs the page around it to grant allow="bluetooth"; without that, Chrome refuses it.

Link (BLE MTU test)

For the test the radio must send unpaced: over the cable run bt pace 0 0 (bench build). Web Bluetooth can't ask for or read the MTU, so it is measured: no notification is longer than MTU-3.
